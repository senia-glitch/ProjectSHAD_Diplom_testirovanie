# Тестирование учеников

Система тестирования: преподаватель создаёт тесты из заданий разных типов, выдаёт и отзывает доступ
каждому ученику, видит результаты и ставит личную оценку. Стек: event-infra + core-package + fastbase,
PostgreSQL 17, Python 3.14, интерфейс без фреймворка в `frontend/` (личный дизайн).

## Правила

- Роль выбирается при регистрации: **преподаватель** или **ученик**. Тест создаёт только преподаватель.
- Доступ к тесту преподаватель включает и выключает для конкретного ученика в любой момент.
  Без доступа ученик не видит тест и не может отправить ответы.
- Результат видит только проходивший ученик и автор теста. Если тест удалён — результаты удаляются.
  Если тест изменён (новая версия) — ученик больше не видит прежние результаты; преподаватель видит их
  с пометкой «прежняя версия теста».
- Правильный ответ и баллы в задании необязательны. Задания без ответа проверяет преподаватель.
- Шкала: «удовлетворительно», «хорошо», «замечательно». Автооценка — по доле баллов за автопроверяемые
  задания и порогам теста (по умолчанию 60 % и 85 %); минимум — «удовлетворительно». Если автопроверяемых
  заданий нет, автооценки нет. Преподаватель ставит под результатом свою оценку и комментарий.
- Ученик может проходить доступный тест несколько раз; каждая попытка — отдельный результат.

## Типы заданий

| Тип | Варианты |
|---|---|
| Выбор ответа | одиночный, множественный, бинарный, выпадающий список, множественный выпадающий список |
| Сопоставление | две колонки, выпадающие списки, перетаскивание, соединительные линии, множественные связи |
| Заполнение полей | одно поле, несколько полей, пропуски в тексте, пропуски с выбором, число, формула, таблица |
| Свободный ответ | краткий, развёрнутый, числовой, с форматированием, несколько блоков |
| Упорядочивание | вертикальный, горизонтальный, кнопками, пронумерованные позиции, слоты |
| Классификация | две категории, несколько, перетаскиванием, выбор категории, множественное распределение |
| Выделение и обозначение | один элемент, несколько, позиция, размещение меток, подпись элементов, элементы схемы |
| Соединение элементов | одна связь, несколько, с общим узлом, сеть, направленные связи |
| Редактирование | правка текста, выделение ошибок, замена, удаление, исправление структуры, вставка |

Перетаскивание работает мышью и касанием; у каждого перетаскивания есть запасной путь — выбрать элемент
щелчком (или Enter) и щёлкнуть по цели. Формулы сравниваются как строки без пробелов и регистра
(`**` = `^`), без математической эквивалентности.

## Запуск (Windows PowerShell, из корня проекта)

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-tested.txt
.\.venv\Scripts\python.exe -m scripts.configure
docker compose up -d db --wait
.\.venv\Scripts\python.exe -m scripts.migrate --database testirovanie
.\.venv\Scripts\python.exe -m app.main
```

По умолчанию HTTP слушает 127.0.0.1:8000; другой порт — переменная `FAT_PORT`.
Демо-данные (преподаватель `demo_teacher`, ученик `demo_student`, пароль `demo12345`, тест со всеми типами):

```powershell
.\.venv\Scripts\python.exe -m scripts.seed_demo --database testirovanie
```

Проверки:

```powershell
.\.venv\Scripts\python.exe -m scripts.check
.\.venv\Scripts\python.exe -m scripts.check --integration --database testirovanie_test
```

Docker целиком: `docker compose build app`, `docker compose run --rm migrate`, `docker compose up -d app --wait`
(внешний порт 18090). Миграции явные: HTTP-старт только проверяет, что схема актуальна.

## Устройство

- `app/scenarios/tasks.py` — типы заданий: проверка структуры, выдача ученику без ответов, автопроверка.
- `app/scenarios/{users,quizzes,test_access,attempts}.py` — бизнес-сценарии core.
- `app/api/v1/routes/` — HTTP; `config/access.toml` — единая политика «роль → внешние сценарии»,
  проверка в `app/policy.py`. Роль берётся из JWT, без токена — `guest`. OpenAPI/docs отключены.
- `frontend/` — `ui.js` (помощники, API, перетаскивание), `widgets.js` (задания), `editor.js` (конструктор), `app.js` (страницы).

Локальный профиль: публичное развёртывание требует HTTPS, настройки секретов, резервного копирования и
ограничения частоты входа.
